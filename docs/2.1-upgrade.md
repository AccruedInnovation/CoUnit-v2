# CoUnit 2.1.0.7 user guide

CoUnit runs tests cyclically in a CODESYS test application. This guide starts with
one passing legacy-mode test, then covers reports and optional catalog execution.
See the [recorded validation scope and limitations](upgrade-plan.md), and
confirm the exact installed provider before use.

## Install and pin

Install [counit_2.1.0.7.compiled-library](../counit_2.1.0.7.compiled-library)
through the CODESYS Library Repository. In the test application's Library Manager,
select **coUnit - A unittest framework for CODESYS, 2.1.0.7 (www.co5e.org)** with
namespace `CoUnit`. The [source library](../counit_2.1.0.7.library) is the editable
native container; `PlaintextExport/` is the inspectable source. Retain the license
notices. The examples qualify library functions; if existing tests use unqualified
calls, adjust the reference's **Qualified access only** setting as needed.

## First passing test

In a disposable test application, create this function block. Its body runs only
when the test is active; the multiplication is a one-invocation observation.

Suite declaration (DEC):

```iecst
FUNCTION_BLOCK FB_FirstTest EXTENDS CoUnit.FB_TestSuite
VAR
    _actual : DINT;
END_VAR
```

Suite implementation (IMP):

```iecst
IF CoUnit.TEST_GUARDED(TestName := 'SixTimesSeven') THEN
    _actual := DINT#6 * DINT#7;
    AssertResult(Passed := _actual = DINT#42, CheckId := 'arithmetic/product',
        Message := 'Multiplication result', ExpectedText := '42',
        ActualText := DINT_TO_STRING(_actual), Detail := 'This invocation');
    CoUnit.TEST_FINISHED();
END_IF
```

Create a program with one suite instance, and assign the program to one cyclic
task. Use a fresh writable path in the test runtime; the example path below must
be changed if it is not writable there.

Program declaration (DEC):

```iecst
PROGRAM PRG_Test
VAR_OUTPUT
    TestComplete : BOOL;
END_VAR
VAR
    Suite : FB_FirstTest;
    Init : BOOL;
END_VAR
```

Program implementation (IMP):

```iecst
IF NOT Init THEN
    CoUnit.GVL_coUnit.xUnitFilePath := 'first-test.xml';
    Init := TRUE;
END_IF
CoUnit.RUN();
TestComplete := CoUnit.GVL_coUnit.coUnitRunner.AreAllTestSuitesFinished();
```

Build and download the test application, then let the task run until completion
and report publication. Expect suite `FB_FirstTest`, case `SixTimesSeven`, one
assertion and a passing result, with `NORMAL` run disposition. Verify the actual
class/instance identity and fresh file path in your project. `TestComplete` is
not proof of a passing test or a completed report write. Inspect the raw report;
[report acceptance](../REPORTING.md) describes the checks. This illustrative
example has not been independently native qualified.

For a separate failure probe, use a separately identified test application and
change both the comparison and expected text to 43. Expect one failed case with
`arithmetic/product`, expected 43 and actual 42. Keep it outside normal passing
selections. The [diagnostic arithmetic example](examples/diagnostic-arithmetic.md)
also shows progress reporting and its own positive and negative expectations.

## Runner ownership

Suite instances extend `CoUnit.FB_TestSuite` and register during initialization.
Instantiate only the suites in the intended inventory. Call exactly one of
`CoUnit.RUN()`, `CoUnit.RUN_IN_SEQUENCE()` or `CoUnit.RUN_CONTROLLED()` once per
scan from one owning task; do not also call suite instances. Continue calling the
runner until finalization and report publication finish. Use a finite host timeout.
`TEST()` alone is not a control-flow guard. Prefer `TEST_GUARDED` or catalog
`BeginCase` and keep stateful fixtures and phases in suite-owned storage.

## Reports and JSON

XML publication is enabled by default. Bind `CoUnit.GVL_coUnit.xUnitFilePath` to a
fresh writable path before the first runner call. Optional JSON is disabled by
default. To enable it, set the `DiagnosticJsonEnablePublish` **library reference
parameter** to `TRUE` in the application's Library Manager before building; do
not assign the constant from program code. Bind a distinct fresh
`CoUnit.GVL_coUnit.DiagnosticJsonFilePath` before the run. XML and JSON have
independent publication outcomes. Preserve and validate every requested report;
`WRITTEN` means the file committed, not that the test passed. See
[report acceptance](../REPORTING.md).

## Legacy run context

Legacy `RUN` and `RUN_IN_SEQUENCE` can be used without embedded run identity. To
bind run/build/target identity, call `CONFIGURE_LEGACY_RUN` once from the owning
task before the first runner call, retain its BOOL and proceed only on TRUE:

```iecst
_configured := CoUnit.CONFIGURE_LEGACY_RUN(
    RunId := 'fresh-run-id', BuildId := 'exact-build-id',
    TargetId := 'exact-target-id', InSequence := FALSE);
```

Use FALSE with `RUN`, TRUE with `RUN_IN_SEQUENCE`. RunId and TargetId are 1–63
stored bytes; BuildId is 1–64. A rejected or late configuration is not retried
every scan. Configuration adds run/build/target identity, but legacy suite,
case and row IDs remain empty and legacy Selected/Started flags do not acquire
catalog semantics. Reconcile actual class/name, outcome and assertion counts.
The sequence delay uses the inherited TIME/TON millisecond domain.

## Catalog preparation and capacity

For large catalogs override `DescribeNext():BOOL`: establish the stable suite
identity on the first call, declare at most one case per call, return FALSE while
pending and TRUE when complete. The default implementation calls legacy
`Describe()` once. Legacy declaration work remains synchronous and is not
implicitly time-bounded. Declaration methods must not invoke setup or the DUT.

Configure ACK accepts identity/deadlines; wait for `Status.CatalogReady` before
list/select/start. Subsequent scans perform one suite step. Setup uses a finite
`RunTimeout` interval; Start begins a fresh execution interval. Setup errors,
timeout and cancellation terminate through the existing bounded paths without
body entry. The framework cannot preempt arbitrary user code.

Project-local provider parameters are capacities, not expected execution counts:

| Parameter | Meaning |
|---|---|
| `MaxNumberOfTestSuites` | Registered suite bound; default 32 |
| `MaxNumberOfTestsForEachTestSuite` | Catalog records per suite; default 2048 |
| `MaxNumberOfAssertsForEachTestSuite` | Admitted assertion calls per suite invocation; default 2048 |
| `xUnitBufferSize` | Reserved XML buffer; default 1048576 bytes |
| `xUnitEnablePublish` | XML publication; default TRUE |
| `DiagnosticJsonEnablePublish` | Independent optional JSON publication; default FALSE |
| `LogExtendedResults` | Extended result logging; default TRUE |
| `TimeBetweenTestSuitesExecution` | Sequential inter-suite delay; default TIME#0ms |

Set these on the application's library reference before build and confirm their
native readback after build. A case page's `MaxAssertionsPerInvocation` and report
`assertions` retain that case's maximum in one invocation, not cumulative calls
across scans or unique source sites. Expected counts come from the selected
fixture's oracle and observations. Zero-assertion setup failure/cancellation is
valid failure evidence, never a reason to invent assertions.

`Status.SelectedCount` and Start's `ExpectedSelected` count matching catalog
rows, including a selected disabled row. They do not count bodies that will run.
Selecting the complete three-row guard suite therefore requires
`ExpectedSelected=3`; its expected execution is two started/passed cases and one
selected disabled skip. Excluded rows remain in the complete report inventory.

## Write and select tests

For an existing suite, guard every effect:

```iecst
IF CoUnit.TEST_GUARDED(TestName := 'PressureValid') THEN
	// Set inputs, call the DUT, save observations, then assert.
	AssertTrue(Condition := _pressureValid, Message := 'pressure is within range');
	CoUnit.TEST_FINISHED();
END_IF
```

Legacy `TEST()` remains a declaration call. Statements after it still execute;
wrap them explicitly when migrating. Guarded entry enables strict definitions.
New catalog suites are strict from preparation onward.

For parameter rows, override `Describe`, call `SetCatalogIdentity` and literal
`DefineCase(CaseId, Name, RowKey, Tags, Disabled)` declarations, and save the returned
handles in suite-owned variables. Use `IF BeginCase(Handle := ...) THEN` in the
body. IDs and row keys are case-sensitive, at most 63 stored bytes, and distinct
from display names and within-run handles. Tags use `|` separators. Describe
declares descriptors only; it must not call setup or a DUT. See the complete
[catalog example](examples/catalog.md) and generated `upgrade_catalog` fixture.

`AssertResult` is the supported domain assertion transaction. It admits/counts
once and records through the built-in failure path. Its strings are bounded
`T_MaxString` inputs; callers must disclose any truncation before submission.

Inside a guarded case, a domain check can report:

```iecst
AssertResult(Passed := FALSE, CheckId := 'domain/limit',
	Message := 'value exceeds limit', ExpectedText := 'limit=10',
	ActualText := 'value=12', Detail := 'configured upper limit');
```

All five text inputs are `CoUnit.T_MaxString` (`STRING(255)`). The bounded
message joins CheckId, Message and Detail; expected and actual are stored
separately. This does not serialize arbitrary structures or promise unlimited
report text. Use short stable domain IDs and concise text; disclose any truncation
before submission. Capture each required return and output before asserting,
including the original decision, reason, relevant identity and sampling point.
A later observation is not the original decision frame. Keep independent
obligations as separate checks; use `AND_THEN` for Boolean conjunctions and
never put required effects in assertion operands.

`ReportPhase(Phase, StepId)` returns BOOL and requires the runner-owned active
test context. `SETUP`, `BODY`, `CLEANUP` and `COMPLETE` are valid; `IDLE` is
not. StepId may store at most 63 bytes. Check the return while executing: an
invalid executing call must remain visible. FALSE during discovery or inactive
replay is not a product failure and must not reset or finish a fixture. The last
accepted call is progress, not a history: it does not wait, drive equipment,
advance a clock, perform cleanup or prove completion. `COMPLETE` is a label;
`TEST_FINISHED` and final reports determine completion. Report useful setup,
body, waiting and cleanup milestones.

A complete guarded method, including a separately selected negative variant, is
shown in [diagnostic arithmetic](examples/diagnostic-arithmetic.md).

Generic `AssertEquals` is the full-length STRING/WSTRING comparison path: pass
writable variables of their actual declared size. Typed STRING/WSTRING APIs keep
their legacy 255-character/code-unit signatures. Diagnostics remain bounded and
include truncation markers. Generic non-string equality remains representation
equality, including padding. REAL/LREAL tolerance semantics are unchanged; failure
diagnostics now include finite IEEE bits and the applied Delta.

## Run, observe, cancel and rerun

For catalog execution call `RUN_CONTROLLED(Exchange := ...)` cyclically from one
task. Write the command payload first and an increasing RequestId last; wait for
matching AckId. Configure with fresh run/build/target identity and deadlines,
wait for `CatalogReady`, select, and Start with the independently known selected
count. Cancellation is cooperative: acknowledgement alone does not prove cleanup
or completion. Status, publisher outcomes and the final reports are separate.
See the [catalog example](examples/catalog.md) for command ordering.

A product reset does not reset CoUnit registration or external files. Use a fresh
application and fresh run-owned reports for an ordinary rerun; do not assume an
arbitrary warm reset is safe. The [qualification record](upgrade-plan.md)
describes the one bounded retained-session warm-reset journey and its limits.

## Fixtures, clocks and result detail

Use persistent `FB_CoUnitFixture` and `FB_CoUnitExpectation` instances. Their
explicit keys contain run, suite, case, row, attempt and step identity. The fixture
copies a valid interface binding; caller rebinding cannot redirect callbacks.
Setup failure suppresses body entry. Cleanup covers entered/partially acquired
setup, preserves the first body cause, and has its own terminal outcome/budget.
Preserve the first body failure even if cleanup, timeout or capture later fails;
report cleanup separately. The assertion count is the historical maximum per
invocation, not a total of distinct checks across scans.
Call ReportFixture with PENDING after entering setup, then the helper's final
cause/outcome before TEST_FINISHED. ReportPhase supplies useful named progress.
Finishing required cleanup while pending becomes an ERROR/incomplete result.

Temporal helpers observe once per cooperating invocation. EVENTUALLY_TRUE/STEP
accept TRUE at the exact deadline and fail a first TRUE afterward. REMAINS modes
fail a contrary observation, otherwise pass the first matching sample at or after
the duration. They cannot observe between scans. Use LTIME() normally or explicit
logical timestamps for deterministic tests; logical time does not disable the real
run/host deadline. See [fixture and temporal examples](examples/cooperative-fixture-and-expectation.md).

### Report identity

Schema 2 includes run/build/target and generation, suite/case/row identity,
selection, execution and fixture details. `RUN_CONTROLLED` provides catalog
identities. In .6 legacy mode, `CONFIGURE_LEGACY_RUN` supplies run/build/target
identity, but no catalog identities or catalog semantics for Selected/Started.
Without that configuration legacy identity remains empty. Verify classic
class/name and outcomes separately. Historical JSON format 1 remains readable by
the parser; see [report acceptance](../REPORTING.md).

## Allocation and migration

Snapshots alias persistent canonical records after finalization instead of copying
names and failure text into another capacity-sized tree. Public pages copy bounded
values. Legacy result storage is optional in allocation: bind caller-owned
`ST_TestSuiteResults` with `BIND_LEGACY_RESULTS` before RUN when needed. The legacy
I_TestResults availability query remains false without that binding. Never retain
a snapshot/legacy reference across application destruction or a new download.

The existing library parameters size suite/test/assertion capacities. Default
bounds remain 32/2048/2048; larger configured values are not qualification claims.
`GVL_CoUnitReporting.RecordsPerScan` defaults to 16 (effective range 1..1024) and
bounds terminalization, snapshot preparation, optional legacy projection and log
traversal. `LogPassedCases` defaults false. Publication keeps the existing fixed
chunks and staged commit/recovery. Budgets do not bound arbitrary user code or
every synchronous filesystem/log operation. Native SIZEOF/capacity/timing evidence
must accompany a supported profile; measurements are not inferred from source.

Obsolete trackers, raw conversion helpers and former file/XML writers moved to
`compatibility/2.0.1.0-obsolete` and are absent from current packages. The 60
preserved legacy declarations still match their reference signatures. Consumers
depending on archived internals must migrate; do not import that archive back into
a current library. Automatic retries, arbitrary in-place DUT resets, concurrent
mutation, assertion-history streams and large artifact services were not added.
